# contoso-event-pack

Version: 2026-10-17. Reusable instructions, not evidence or pre-generated results.

## Operating rules

- Execute only the procedure matching the user's requested work; never run the entire collection automatically.
- Use the user's language for all responses, documents and drafts. Use only that language's procedure below; English is the default only when the request does not establish a language.
- Derive the actual run name and output folder from the selected Action_Register.xlsx metadata. Never ask the user to paste a technical run ID when its original cloud location is available. If its location cannot be verified, ask one short question before writing.
- Use only the selected scenario evidence. BEFORE is preparation, CHANGE is a selected availability update, AFTER is an explicitly staged post-event snapshot. Skill instructions are not evidence that a business decision occurred.
- Save real files and actual unsent Outlook drafts, then report their verified cloud links. Never pass a chat response, approval preview or workspace-only copy off as a saved result.
- Verify the exact saved cloud originals, not only a workspace or live-render copy: required page counts, readable tables, requested fonts and real source hyperlinks must survive saving. If verification fails, report that boundary rather than claiming completion.
- To correct a saved Office document, reattach that exact OneDrive or SharePoint file and edit it in place. Editing does not require deleting or replacing it. Do not create _Arial or _final alternatives, or ask the presenter to fix formatting manually.
- During BEFORE or CHANGE work, the action workbook's metadata identifies the run. Task rows from a later AFTER execution are not planning evidence and must not be imported into the preparation pack.
- No external contact, sending, posting, invitations, calendar changes, booking, payment or automation. Draft recipients must be the named approved demo-tenant mailboxes in the selected evidence; no other recipients, CC or BCC.
- Do not infer booking authority, spending approval, availability, completed tests, prices, actual costs or success criteria. Missing evidence stays an explicit question.
- File edits require individually reviewed one-time approvals, never Always allow. An error may leave partial edits: reread the actual original before retrying. Stop and report a failed operation instead of repeating the same failed batch blindly.
- Preserve immutable inputs. Only the post-event procedure edits the selected original action workbook. Never overwrite the baseline or another run.
